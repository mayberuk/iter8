# Point at a running page, hand the round to its session

## Objective
Mark up a running web page (an agent's mock or an app built with an agent) by clicking elements and sections, then hand the round of notes to the Claude Code session that owns that page — including when the browser is on the laptop and the session is on the devbox over SSH.

## Problem / Context
Requirements: `.claude/work/.from-grillme.md`. Prior art: reviewdesk's annotate system, inventoried in `docs/briefs/web-annotate/`. Two loops: mock iteration and live-site fixes. Single user. v1 pages are agent-written HTML files and local dev servers; deployed/staging later. Dealbreakers: buggy, laggy, fighting Claude Code's primitives.

## Current direction
An annotating proxy runs on whichever machine the session runs on (devbox over LAN, or laptop alone), injecting the overlay into a dev server or a folder of HTML. One per-machine service, started on demand by the first open and exiting when idle, owns every page's proxy port, the live-session list and each session's inbox of rounds.

## Decisions
- **Overlay reaches the page through a proxy on the session's machine** — only option meeting the SSH constraint with zero per-project setup; one port per page gives session pairing; reaches localhost-only dev servers from the laptop. Must also work laptop-only with no LAN (then localhost = secure context, window can be spawned). Rejected: browser extension (per-browser install/update cycle, still needs the devbox server; kept as a possible later front door for deployed sites), per-project hookup (setup per project/framework, edits project code), tool-driven browser (over SSH it opens on the devbox/TV, not the laptop).
- **One on-demand per-machine service** owns proxies, live sessions and inboxes; auto-started, exits when idle — needed so a page can say its session is gone, offer reattach, keep drafts, and host self-opened pages. Rejected: process per page (no reattach, self-opened pages homeless, orphans), installed systemd/launchd service (install/update step per machine, the reviewdesk reinstall pain).
- **Packaging: a plugin in cc-plugins whose binary's CLI is the real interface** (open, rounds, show, done — usable from any agent or terminal); Claude Code hooks/skills are a thin layer over it, so a Codex layer can follow and it can be split into its own repo later. Rejected: Claude-Code-only plugin (designs Codex out; toolchain is Claude Code + Codex), separate repo + thin plugin (two installs that drift, outside the release discipline).
- **Overlay look settled on sketch 4** — Lens structure, tactile flat aesthetic (depth from a darker shade of each element's own colour, no blurred shadows, faint warmth), Figtree-family rounded UI font, bespoke vector intent/status glyphs, official Claude mark as Claude's avatar, light + dark themes from one token set (dark background warmth cut to ~75%). Sketch 4 is the visual reference for the build. Amended 2026-10-10: sketch 4 remains the structure, layout and interaction reference and historical colour baseline; faint warmth becomes neutral grey, retaining every neutral token's OKLCH lightness with chroma 0 and leaving semantic colours unchanged. Reddit Sans replaces Figtree for all prose; JetBrains Mono replaces Spline Sans Mono only for file paths, line numbers and keyboard keys (both OFL, variable, embedded as pinned woff2). MingCute line icons cover every UI icon, initially with four Fluent 16 regular exceptions (pick, region, screenshot dock tools and auto-theme); the batch review kept the original hand-drawn tilted pick pointer instead of Fluent's cursor, so only region, screenshot and auto-theme use Fluent. Bespoke intent pictograms and status glyphs stay. Light neutralisation was pending the batch review; Biruk confirmed it on 2026-10-10. Palette and icon authority: the iteration-2 assets `dark-neutral-tokens.css`, `palette-remap-reference.ts` and `icons-mingcute-fluent.json` from the look pass. Playful springs stay everywhere; springs that animated layout now drive transform with the same curve.
- **Devbox pages reach the laptop through a fixed pool of SSH forwards** (one-time laptop SSH config, e.g. 3990–3999 → same ports), so every page is localhost on the laptop and cookies, service workers, the Next origin check, clipboard and screen capture work; plain LAN http stays as a fallback marked "limited mode" in the dock with what is off. Laptop-only needs none of this. Rejected: plain LAN http only (breaks Secure-cookie logins, SW, clipboard, capture), Tailscale HTTPS (needs HTTPS enabled + per-port serve permission, hostnames in public cert logs; possible later add-on for phone review). The service must detect a pool port already taken on the laptop and say so. Amended 2026-10-10: laptop-side `iter8 connect <host>` forwards the pool on one dedicated connection and reconnects after sleep or a network change, replacing the one-time laptop SSH config and hand-typed `ssh -L` line; the opt-in LAN listener stays unbuilt.
- **/clear follows the terminal** — the page re-pairs to the cleared session automatically; rounds arrive in the fresh context, labelled. Rejected: treating /clear as session gone (/clear resets context, it doesn't abandon the page).
- **A dead session offers reattach** — the page says the session ended, disables Send, and lists live sessions to attach to (as in sketch 4); drafts survive.
- **Delivery is push + pull into one inbox** — Send wakes an idle session through a stable hook and waits for the turn to end if busy; any next prompt ("I've left comments") also picks it up. Rejected: pull only (Send would just save). Amended 2026-10-10: the mod starts the idle turn where mods run; shell hooks retain the fallback wake and pull path.
- **reviewdesk migrates later** — build standalone first; nothing reviewdesk-specific in the design now.
- **A note carries:** page URL, a shadow-DOM-aware selector, role/name/text, element box, viewport, theme, cropped screenshot, intent (fix/change/question/keep), the note, the nearest landmark and surrounding text, a best-effort component + file:line labelled with how it was found and how sure (e.g. exact-React, file-only-Vue, none) and framed to the agent as a lead to confirm, the element's computed styles, and recent console errors only. Everything beyond the pick itself is captured after the composer paints so it cannot cost a keystroke. The inspector chip shows the confidence label rather than always looking certain. Rejected: lean framework-blind (agent greps every time, ambiguous on repeated text), forensic (HTML snippets, full console, network, click trail — the click-time capture weight that froze reviewdesk, and noise for most notes).

- **Revised: the tool lives in its own repository; cc-plugins keeps a thin Claude Code plugin** that pins a tool version (supersedes the packaging decision above). The tool needs a compiled service, a TypeScript overlay build and end-to-end tests against real Vite/Next fixture apps; cc-plugins' per-commit version-bump hook would fight a long iterative build; reviewdesk and Codex will consume it too. The drift risk that ruled this out earlier is now covered by review-forced decision 6's version handshake.
- **Planned as an initiative**: contract (overlay↔service protocol + CLI) first; then service/proxy/CLI and the overlay in parallel; then per-framework source resolution and the Claude Code layer.

- **Stack: TypeScript on Bun for the service, proxy and CLI; Preact + Signals for the overlay.** Biruk chose Bun over the recommended Go: one language with the overlay, reviewdesk's portable annotate code (locator, capture, batch file) reused directly, protocol types shared with no codegen. Verified 2026-10-09 (Linux only): compiled Bun cold start 1.3 ms vs Go 0.43 ms, so per-prompt hook cost is negligible; `HTMLRewriter` streams (first chunk ~0 ms against a 600 ms upstream), and `fetch()` decodes gzip/br/zstd but leaves stale content-encoding/content-length headers the proxy must strip; no WebSocket pass-through — the proxy bridges: open the upstream socket first, pass its negotiated subprotocol into the upgrade, queue messages until it opens (tested); unix-socket servers and detached daemons (PPID 1, own session) work. Costs: compiled binaries are 62 MB (darwin-arm64) / 81 MB (linux-x64); a cross-compiled darwin binary may need `codesign` — unchecked on a Mac. Preact 11 (4.6 KB gz) attaches direct listeners, so shadow-DOM retargeting and host pages that stop propagation don't break it (Solid delegates to document and would). bippy 0.7.3 (MIT) injected late still reads fibers via `__reactFiber$` DOM properties. Rejected: Go (recommended; better binary size, but a second language and codegen), Rust, Solid (document-level event delegation), Lit, vanilla.

- **Name: iter8** (kept knowingly: iter8-tools/iter8 is an existing Apache-2.0 Kubernetes project, and npm/PyPI `iter8` packages exist — harmless while private; revisit before publishing). Repo `~/dev/iter8`, CLI `iter8`.
- **Server layering: Hono (4.13.x) + Zod + Hono's typed client for the overlay↔service API and its live socket; plain `Bun.serve` for proxying app traffic and bridging HMR sockets.** Neither Hono nor Elysia proxies websockets — both wrap Bun's server upgrade — so the bridge is ours either way, and a framework router has no place in front of every app request. Hono reuses reviewdesk's Hono/Zod annotate code and lets the Zod schemas be the protocol contract. Hono's docs warn header-modifying middleware breaks websocket routes, so the origin/token check (review-forced decision 1) runs before the upgrade, not as ordinary middleware. Rejected: Elysia 1.4 (nicer Eden types, but Bun-first and its own schema system — reviewdesk's Zod would need porting), framework for all traffic.

## Review-forced decisions
Adversarial review 2026-10-09 (`.claude/reviews/2026-10-09-web-annotate-design/`): Codex gpt-6.1-sol xhigh and Opus high both denied "meets every requirement with no hidden assumption or conflict". All 25 findings accepted, merged into these 13. Hooks claims verified against code.claude.com/docs/en/hooks (asyncRewake timeout enforced; Stop skipped on user interrupt; 10,000-char cap, overflow becomes a file Claude isn't told to read).

1. **Authority boundary** (critical). Service and proxies bind 127.0.0.1; the LAN fallback is a separate opt-in listener, off by default. `open` mints a per-page capability token injected into the overlay script (never a cookie); every overlay→service call, HTTP and websocket, sends it in a custom header, which forces a CORS preflight the service refuses for foreign origins. Overlay endpoints sit under a reserved path prefix and require Origin = the page's own origin. Session administration (pair, reattach, rounds, done) goes over a local control socket, not HTTP. Amended 2026-10-10: the mod speaks HTTP over that same unix control socket, authenticated by its file permission; no TCP administration listener or token is added, and the opt-in LAN listener stays unbuilt. Origin/Host rewriting applies only to upstream app traffic, only where needed.
2. **Untrusted-content boundary.** Hooks never inject note content — wake and pull deliver a neutral pointer only ("Review round R12 from larkspur · 7 notes — run `<cli> show R12`"). `show` separates Biruk's authored notes from captured page data (DOM text, console errors, styles, source leads), which is fenced and labelled untrusted. Captured strings never become CLI arguments. Amended 2026-10-10: page chat messages carry their text into the session, labelled as typed on the page rather than in the terminal, only through the Claude Code mod; hooks still carry only pointers.
3. **A page pairs to the Claude Code process, not the session id.** Identity = PID + process start time (from the hook's process ancestry) + a pairing generation; `CLAUDE_CODE_SESSION_ID` is a label on it. /clear and /resume relabel the same process (SessionEnd clear|resume = relabel pending, not gone). Liveness = local PID + start-time check, possible because service and session share a machine — this closes the crash question. States: live, busy, unknown, gone; revalidated at Send and while rounds are queued, so a death after acceptance shows as a delivery failure. Stale tabs, waiters and generations are rejected.
4. **Durable rounds with explicit states.** Send persists to disk before acknowledging; stable round ids, idempotent retries. draft → queued → announced → claimed (agent ran `show`) → per-note done/answered. Announcement is non-destructive and at most once per (process, round); only `show` claims. Unclaimed rounds carry across relabel and reattach.
5. **Wake listener lifecycle.** One listener per process, armed on SessionStart (all sources), Stop and UserPromptSubmit (Stop is skipped on Esc), with a long explicit hook timeout; a new listener replaces the old. The service tracks "listener armed" and the dock shows "wakes now" vs "queued until your next prompt". Busy/idle is not inferred from Stop alone. Amended 2026-10-10: the mod's long-poll replaces the asyncRewake listener where mods run, and the hook listener yields to it.
6. **Service lifecycle.** Launched detached (own process group — a Claude Code background task dies when Claude exits) by any SessionStart hook (no-op if running) and by `open`. Single instance: lock + fixed control-socket bind, readiness handshake, callers join an in-progress start. Idle = no live paired processes, no open page connections, no unclaimed rounds, for N minutes. Drafts, rounds and pairings on disk outside the versioned plugin dir. Protocol/schema version handshake: a mismatched service drains and re-execs from the current install.
7. **SSH pool verified from the browser side.** The devbox can't see laptop ports, so the injected script and a landing page check they reached the expected service (machine id + page id + token) and say "port 3992 on this laptop isn't your devbox" otherwise. Forwards ride one dedicated connection (ControlMaster/ControlPersist or a `-N` keeper, ExitOnForwardFailure=yes), not interactive terminals. Amended 2026-10-10: laptop-side `iter8 connect <host>` keeps one dedicated SSH tunnel to the devbox's port pool up and reconnects after sleep or a network change; it prefers the Tailscale address when both machines are on the tailnet and the devbox is an online peer, otherwise falls back to plain SSH with the user's own config. Every ssh it spawns passes `ControlPath=none`, replacing the ControlMaster/ControlPersist option so forwards never ride a ControlMaster the user owns. A unix socket is reverse-forwarded into the devbox's iter8 home; `iter8 open` on the devbox hands each new page's URL to it so the page opens on the laptop. Any mix of macOS and Linux works; the opt-in LAN listener stays unbuilt. Laptop-only uses a non-overlapping range. Pool range sits away from common dev-server ports; in-use devbox ports are skipped.
8. **Proxy treatments.** Strip conditional request headers on HTML (no 304 un-injected pages); decode-aware streaming injection, no whole-body buffering; add the injected script's hash/nonce to CSP; rewrite Location headers aimed at the upstream origin; websocket pass-through with subprotocol and query intact. Multi-port apps: `open` can declare extra upstreams, each with its own pool port; a failed request to an unforwarded localhost port surfaces in the dock. A page the proxy can't inject into fails visibly with the reason, never as a silently broken page.
9. **Browser-origin isolation.** Ports don't isolate cookies (RFC 6265 §8.5) and a reused port inherits the previous app's service worker and storage. A project keeps a stable port across sessions, never reused for a different upstream; the plan evaluates per-page `*.localhost` hostnames for cookie isolation across Chrome, Firefox and Safari.
10. **Performance budgets.** A tiny synchronous identity snapshot at pick time (selector, role/name/text, box, render generation) — survives virtualized/recycled nodes. Enrichment is bounded (reviewdesk's 2-viewport / 300-node crop cap kept), runs in chunks that yield to input, is cancellable, omits gracefully over budget, and checks the target is still the picked instance (stale captures marked). Computed styles only where they differ from parent/defaults; source-map symbolication runs in the service, not the page; inspector confidence resolves after the pick, never on hover; hover outline is frame-throttled. Acceptance gate: no main-thread task over 50 ms while typing in the composer on the heavy fixture with enrichment running. Amended 2026-10-10: this replaces the ≤ 250 ms typing gate. Hover and pick hold 60 fps at normal speed (no frame over 16.7 ms). With Chromium's CPU throttled 4× (standing in for battery power-saving), no task runs over 50 ms and overlay-attributable dropped frames are at most the larger of 2 frames or 10%, beyond the page's own. Pins are laid out in document coordinates and move in the same frame as the page when scrolling; elements in their own scroll containers retain a listener. Every animation is compositor-only (transform and opacity). Budget tests live in `*.budget.test.ts` files, run serially by the gate after the parallel suite; CI calibrates the CPU throttle rate to the host's speed (Lighthouse benchmarkIndex style). Amended 2026-10-13: the crop's two-viewport cap is replaced. It judged the container around a drag instead of the drag, so most real drags were refused (75 of 80 on the playground's table page), and clone cost follows node count, not height. A capture now clones the smallest element holding the clip, prunes it to what intersects the clip (outside elements stay as empty boxes so borders and row lines survive), keeps the 300-node cap, caps the output at 7680×4320, drops CSS custom properties from the clone (about half of the SVG text) and yields between serialise, encode and decode, so no capture task runs over 50 ms at 4×. Region notes now carry a screenshot too.
11. **Static mocks reload and pins re-anchor.** Folder mode watches files and pushes a reload over the overlay's own connection; drafts live in the service keyed by page id, so they survive reloads; pins re-anchor by selector + role/name/text + box and unresolved ones show "moved" rather than re-pinning silently.
12. **Source confidence by detected build combination.** Next on webpack → approximate (silently returns generated lines); Vue → file only; Svelte 4 → approximate; a candidate path must resolve inside the project, else none. Amended 2026-10-10: static folder picks map to file:line in the service without adding attributes to the page DOM; parse5 is approved, and folders served from `dist/` or `build/` report "outside project".
13. **Agent-neutral core.** The CLI pairs by an opaque owner id (`open --owner`, `rounds --owner`); the Claude Code layer supplies process identity, wake and pull. Codex v1 is pull-only — its background hooks don't start an idle turn — and Codex push is out of v1.

## Decisions after hand-off (2026-10-09, initiative intake)
- **Each page gets its own `*.localhost` hostname**, routed by the service on the Host header (e.g. `larkspur.localhost:3990`). Supersedes review-forced decision 9's stable-port rule and shrinks decision 7's pool to a few forwarded ports: distinct hostnames isolate cookies, storage and service workers, so a port is no longer tied to one project and the pool cannot run out as projects accumulate. The foundation part checks it in Helium first; if Helium does not treat `*.localhost` as loopback and a secure context, decisions 7 and 9 stand as written plus a rule for reclaiming old ports.
- **Browsers: Chromium-based only in v1**, aimed at Helium on the laptop. Firefox and Safari are out; scenario tests run Chromium.
- **Releases from a private GitHub repo `mayberuk/iter8`.** The foundation part owns the release build (linux-x64, darwin-arm64, the macOS codesign check); the Claude Code plugin downloads a pinned release with the user's `gh` login.
- **Agent notes are in v1.** The agent can pin its own notes on the page (`iter8 note`, anchored by selector plus role/name/text), shown with the agent's avatar and re-anchored like Biruk's pins; one it cannot resolve shows as unanchored rather than vanishing. A note's author (Biruk or a named agent) is part of the protocol.
- **Repo standards adopted from reviewdesk**: `.claude/rules/` (engineering canon, stack, testing, protocol, overlay, file safety), Biome, knip, dependency-cruiser, strict `tsc`, one `bun run check`.
- **Test rig in wave 1.** The foundation part builds `harness/` — rig, a stub agent session standing in for Claude Code, a mock service for the overlay to develop against, and a long-task probe for the typing budget — so every later part proves its behaviour with scenario tests against the real service, real fixture apps and headless Chromium.
- **Layout follows reviewdesk**: binaries under `apps/` (`apps/iter8` for service, proxy and CLI; `apps/overlay`), shared code under `packages/` only once a second app imports it.

## Decisions after iteration 2 (2026-10-10)
- **Mod on the control socket.** The Claude Code mod uses HTTP over the existing unix control socket, authenticated by the socket's file permission (0600 inside the 0700 iter8 home); an owner or PID routes to a session rather than granting authority. Rejected: a loopback HTTP endpoint with a per-session bearer token (a second authority surface and a secret to hand over), spawning the CLI for every transcript row (one process per row and no streaming from `$.process.run`), and the undocumented cross-session inbox format. The mod requires Claude Code 2.1.296+, registers only at SessionStart, is off in non-interactive sessions, and shows the live round in a Claude Code pane; shell hooks remain the fallback in the VS Code panel, `-p` and desktop WSL.
- **Finished conversation messages.** The page shows finished messages, loads older ones on demand, and displays a sent message instantly. Rejected: token streaming, which is unavailable for terminal sessions.
- **Page chat through the mod.** Messages are labelled as typed on the page rather than in the terminal and treated like note text. Chat is on by default only for folders and localhost pages (`localhost`, `*.localhost`, `127.0.0.0/8`, `::1`); other pages enable it per page. A session with no live mod channel refuses chat before Send instead of queueing it forever; hooks carry only pointers.
- **Send now between tool calls.** Send now marks a queued round; `iter8 hook tool` delivers its neutral PostToolUse pointer, wrapped as `additionalContext`, and Claude fetches the round itself.
- **No waiter takes a round while the session is busy.** A round stays queued until turn end, the next prompt, or Send now between tool calls. Rejected: announcing it immediately to the armed waiter, which leaves Send now only a duplicate pointer that also fires at turn end. The mod reports busy/idle on turn start/complete, including Esc; shell-only sessions miss Stop on Esc, so the round waits for the next prompt, as accepted in the batch review.
- **Performance budgets.** No main-thread task over 50 ms while typing in the composer on the heavy fixture with enrichment running, replacing the ≤ 250 ms gate; hover and pick hold 60 fps at normal speed with no frame over 16.7 ms. At Chromium 4× CPU throttle (battery power-saving), no task over 50 ms and overlay-attributable dropped frames at most the larger of 2 frames or 10%, beyond the page's own. Pins in document coordinates move in the same frame as scroll; animations use transform and opacity only. `*.budget.test.ts` files run serially after the parallel suite; CI calibrates the throttle to host speed.
- **Neutral palette, type and icons.** Neutral grey replaces faint warmth: each neutral token retains its OKLCH lightness with chroma 0; semantic colours stay. Light theme was pending confirmation and was confirmed neutral in the batch review. Reddit Sans replaces Figtree for all prose, JetBrains Mono replaces Spline Sans Mono for file paths, line numbers and keyboard keys only; both are OFL, variable and embedded as pinned woff2. MingCute line replaces UI icons with the initial four Fluent 16 regular exceptions (pick, region, screenshot and auto-theme); the batch review rejected Fluent pick in favour of the original hand-drawn tilted pointer, retaining Fluent for the other three. Bespoke intent pictograms and status glyphs stay. `dark-neutral-tokens.css`, `palette-remap-reference.ts` and `icons-mingcute-fluent.json` are the iteration-2 palette and icon authority; sketch 4 remains the structure, layout and interaction reference and historical colour baseline. Keep playful springs everywhere, using the same spring curve through transform for layout motion; the look audit removes text pills, uppercase tracked mono labels and prose in mono without removing the springs.
- **`iter8 connect <host>` picks a route per attempt.** The laptop runs `tailscale status --json` (from PATH, else the macOS app bundle) and uses the Tailscale address when `BackendState` is `Running` and an online peer matches the host, by name, MagicDNS name or tailnet IP, comparing case-insensitively; otherwise it uses plain SSH with the user's config. On the Tailscale route ssh keeps the alias, so `User` and `IdentityFile` still apply, and adds `-o HostName=<first IPv4>`. The route is re-checked on every attempt because leaving the LAN can change which one works. Rejected: `tailscale ssh` (needs Tailscale SSH enabled on the devbox, where plain ssh to the tailnet address works on any tailnet).
- **`connect` forwards each pool port to the same number.** It learns the pool, the devbox's iter8 home and machine id from `iter8 status --json` run over ssh (parsed with `ServiceStatus.pick`, so a newer devbox build still parses), and forwards `-L P:127.0.0.1:P` because the service binds loopback. Rejected: remapping ports (a page's origin includes its port and the service routes on Host plus port, so a different laptop port breaks routing, cookies and the origin check). A devbox service that is not running is polled every 3 s, since any session or `iter8 open` there starts it; a missing remote `iter8` is permanent. A laptop port already taken retries at the backoff cap, and when this laptop's own iter8 service holds it (the same default pool on two machines) the message names the fix: a different pool in one machine's `config.json`.
- **`iter8 open` on the devbox hands each page to every connected laptop through a reverse-forwarded unix socket.** The laptop listens on `<laptop home>/connect-<pid>.sock` (mode 0600) and ssh `-R` forwards it to `<devbox home>/laptop-<name>-<8 hex>.sock`; the name is fresh every attempt because sshd's `StreamLocalBindUnlink` defaults to `no`, so a stale file from a dropped link would block a fixed name. `open` posts `{ machineId, url }` to each `laptop-*.sock`, waits at most 1 s, unlinks only sockets that refuse or are missing, and never fails because a laptop is gone. The laptop opens (`open` on macOS, `xdg-open` on Linux, one argv element, no shell) only an `http:` URL on a single-label `.localhost` host, on a forwarded port, without credentials, from the machine id it learned at connect time. If sshd refuses socket forwarding, `connect` keeps the port forwards, drops `-R` and says pages will not open by themselves. Rejected: a pull loop that lists the devbox's pages (needs a new control route and CLI command; the push needs only a call from `open`).
- **Every ssh `connect` spawns passes `-o BatchMode=yes -o ExitOnForwardFailure=yes -o ServerAliveInterval=10 -o ServerAliveCountMax=3 -o ConnectTimeout=10 -o ControlPath=none`, and `--` before the host.** `BatchMode` stops a reconnect after sleep from blocking on a hidden password or host-key prompt; those cases are reported with "run `ssh <host>` once". The keepalives notice a dead link within 30 s. `ControlPath=none` keeps our forwards off a ControlMaster the user may own, where killing our process would not drop them and `ExitOnForwardFailure` behaves differently; rejected: ControlMaster multiplexing. `--` comes first so a host can never become an ssh option such as `-oProxyCommand=…`; a host that is empty, starts with `-` or holds whitespace or control characters is a usage error, and every remote command is a fixed argv.
- **The supervisor restarts the ssh child with capped backoff.** Delay is 1 s, doubling to a 30 s cap (the keepalive budget), reset once the tunnel has stayed up 60 s. A 2 s wall-clock tick that arrives more than 10 s late means the laptop slept: the child is killed and reconnected at once instead of waiting for keepalives. The wall clock is the signal because monotonic clocks stop during suspend on macOS and Linux; an NTP step causes at worst a needless reconnect. It gives up only for an auth failure, a host-key failure, a missing remote `iter8` or an invalid host.
- **`iter8 connect` scope.** Any mix of macOS and Linux works; the opt-in LAN listener stays unbuilt. Not built: Tailscale HTTPS or `tailscale serve`, running at login, several devboxes at once, Windows, and opening pages that were already open on the devbox before `connect` started.
- **Iteration-1 bugs fixed by design.** Pins use document coordinates rather than fixed positioning updated a frame after scroll. Whatever the user types into stays on top, with the composer moving clear of the round sheet. Suppress the lost-anchor warning only for notes the agent resolved; retain it for open drafts.

## Decisions for the project and dev loop (2026-10-12)

- 2026-10-12 **Proxy upheld over a framework plugin:** rejected a Vite plugin because a LAN-IP page is not a secure context and loses `crypto.randomUUID` for Send and the clipboard, the service would become LAN-reachable, static mocks have no dev server, and Next needs its own adapter.
- 2026-10-12 **`iter8 run` starts and opens a project:** use its `dev` or `start` script or serve HTML, accept an explicit command after `--`, keep the upstream port stable from the project's realpath with `--port` as an override, open on connected laptops or in the local browser, and stop the dev server's process group on Ctrl-C while keeping pins and pairing.
- 2026-10-12 **`iter8 setup` installs the terminal command and laptop login connection:** `~/.local/bin/iter8` execs `$DATA/current`, the symlink to the newest installed verified release in the plugin data dir, and `iter8 setup <devbox>` installs `iter8 connect <devbox>` at login, amending the earlier exclusion of login startup.
- 2026-10-12 **The laptop follows the devbox's release:** after a successful probe, `connect` updates only when both builds are `compiled` and the devbox is strictly newer, verifies the downloaded checksum and exact version, repoints `$DATA/current` without downgrading, and restarts on the new binary.
- 2026-10-12 **Dev builds use a separate state dir:** `scripts/iter8-dev` defaults to `ITER8_HOME=$HOME/.iter8-dev` and `ITER8_POOL=3970-3973` unless already set, while `dev:claude` selects it through `ITER8_BIN` and the mod reads its home from `iter8 status`, so source builds do not drain the installed service.

## Decisions after the 2026-10-13 hands-on

- 2026-10-13 **Hooks never start or drain the service, and an older iter8 never drains a newer one:** sessions on older plugins pinned older binaries and replaced each other's service on every prompt, timing out the prompt hook. A newer compatible service is used; an incompatible one asks the session to restart.

## Research findings (2026-10-09, scratchpad research-*.md)
- `CLAUDE_CODE_SESSION_ID` is set in Bash-tool and hook processes and changes on /clear — a command run by the agent knows its session without hacks.
- An asyncRewake hook exiting 2 wakes an idle session immediately; nothing injects mid-turn (queues to the turn end). UserPromptSubmit additionalContext caps at 10,000 chars.
- Channels (MCP push into a session) are a research preview needing a dev flag for a personal marketplace — excluded by the stable-surfaces constraint.
- SessionEnd fires on /clear with a reason; crash/terminal close undocumented — liveness needs its own check.
- Prior art: no tool targets one specific session; claude-selector broadcasts to every session via UserPromptSubmit. Agentation has the richest note schema (intent fix/change/question/approve, severity, nearby text, computed styles, source file) but is React-only and PolyForm Shield. react-grab (MIT) maps element to component + file:line via a separate `element-source` package (React, Preact, Vue, Svelte, Solid). AGPL/GPL/PolyForm tools cannot be reused.
- Proxy + live reload (scratchpad research-proxy-hmr.md, source-read, untested): Vite and Next HMR dial the page's own host, so a websocket-passing proxy carries them with no project config. Breaks over plain http on a LAN IP: Next >= 16.2 rejects a non-localhost Origin on HMR (proxy must rewrite Origin/Host + X-Forwarded-Host), gzip+streamed Next HTML needs decode-aware injection, ETag/304 can serve un-injected pages, strict CSP blocks the script, Secure cookies and service workers fail, and the overlay loses secure-context APIs (randomUUID, clipboard, getDisplayMedia). Most of that list disappears if the browser sees localhost or https.
- Element → source (scratchpad research-element-source.md, measured with runtime injection): exact on React 18/19 and Next 16 Turbopack incl. server components when using a current bippy (react-grab 0.2.0); element-source 0.0.5 is stale (first-hook line, null for hook-less components) unless rebuilt on bippy 0.7.3. Next `--webpack` dev returns generated-module lines with no error. Svelte 5 exact; Svelte 4 off by one; Vue file only (no line, slots misattributed); Solid only handler-bearing elements, definition line; Astro exact but its dev toolbar strips the attributes ~100 ms after load. LocatorJS / click-to-component are dead on React 19; build-plugin code-inspector-plugin is exact but needs per-project setup. Not tested: Rspack, Firefox/Safari, Vue 2, Preact.
